## 二、四个云函数，为什么是四个

| 云函数 | 职责 | 超时设置 | 为什么单独拆 |
|---|---|---|---|
| `aiSentinel` | 图像 + 文本判定 | 20s | 耗时长，独立超时；可单独压测、单独换模型 |
| `submitReport` | 入库、去重、结算 | 10s | 唯一写 reports/orders 的入口，权限收口 |
| `api` | 所有读操作 + 后台操作 | 10s | 原型期减少部署单元，action 路由分发 |
| `genReport` | 周报 / 巡逻 / 合并建议 | 60s | 生成类任务最慢，绝不能拖累上报链路 |

关键取舍：**`api` 合并了 8 个查询接口，但 `aiSentinel` 和 `genReport` 坚持独立**。

理由是生命周期不同。查列表要在 1 秒内返回，生成周报可以等 20 秒。放在同一个函数里，要么超时设得太短导致周报失败，要么设得太长让查询接口在异常时挂很久。

## 三、一次上报的完整数据流

```
1. 小程序端
   ├─ wx.chooseMedia 拍照 → wx.compressImage（压缩到 1024px）
   ├─ wx.cloud.uploadFile → 拿到 fileID（选完就传，不等提交）
   └─ wx.getLocation → lat/lng

2. callFunction('aiSentinel')
   ├─ cloud.getTempFileURL：fileID → 公网临时链接（模型只能读 https）
   ├─ Promise.all([视觉判定, 文本判定])
   ├─ 合并结论 → { pass, severity, summary, advice, reason }
   └─ 写 ai_logs（用于算拦截率）

3. 若 pass = false
   ├─ callFunction('api', { action: 'markInvalid' }) → 信用分 -1、无效计数 +1
   └─ 跳结果页，展示温和提示 + 「仍然提交」出口

4. 若 pass = true
   └─ callFunction('submitReport')
      ├─ 粗筛近 24h 同类型工单 → 内存算球面距离
      ├─ 15 米内命中 → 合并进已有工单，mergeCnt+1，紧急度提升
      ├─ 未命中 → 新建工单 + 生成工单号
      ├─ 写 reports 记录（含 aiVerdict 内嵌）
      └─ 结算信用分 + 徽章

5. 管理端
   ├─ callFunction('api', { action: 'dashboard' }) → 指标 / Top5 / 趋势 / 热力点
   └─ callFunction('api', { action: 'orderUpdate' }) → 状态流转，同步回写 reports
```

## 四、管理端怎么接云开发

小程序端可以直接 `wx.cloud.callFunction`，Web 端不行。两种接法：

**方案 A：CloudBase JS SDK（推荐，改动最小）**

```html
<script src="https://unpkg.com/@cloudbase/js-sdk@2/dist/index.umd.js"></script>
<script>
  const app = cloudbase.init({ env: '你的环境ID' });
  const auth = app.auth({ persistence: 'local' });
  await auth.anonymousAuthProvider().signIn();   // 需在控制台开启匿名登录
  const res = await app.callFunction({ name: 'api', data: { action: 'dashboard' } });
</script>
```

在控制台「环境 → 登录授权」里开启匿名登录，然后 `api` 云函数里的 `ADMIN_OPENIDS` 校验就管不住了（匿名用户没有 openid）。

生产环境建议改成：管理端走自定义登录，签发带 `role: admin` 的自定义 token，云函数里校验 `role` 而不是 openid。

**方案 B：云开发 HTTP 访问服务**

云开发支持把云函数暴露成 HTTPS 接口，管理端用 `fetch` 直连，走自定义 header 鉴权。适合要和现有后台系统集成的情况。

本项目 `admin-web/index.html` 是**纯前端演示版**，数据全部本地模拟，不依赖网络也能完整演示所有交互。接真实数据时，把 `MockAPI` 部分换成上面的调用即可，界面代码一行不用改。

## 五、为什么选微信云开发

| 对比项 | 云开发 | 自建 Node + MySQL |
|---|---|---|
| 第一天能跑通 | 半小时 | 一天（域名、备案、证书、部署） |
| 10 天出原型 | 可行 | 紧张 |
| 免费额度 | 够演示和小规模试点 | 服务器成本 |
| 后期迁移 | 有锁定风险 | 自由 |

10 天周期的约束下，云开发是唯一合理选择。锁定风险靠两点缓解：业务逻辑全在云函数里（相当于普通 Node 代码，可迁移），数据结构是标准文档模型。
